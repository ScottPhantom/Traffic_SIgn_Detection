# M0-WP38-R1 orientation-correction QA remediation report

Date: 2026-10-22  
Status: `WP38_R1_AWAITING_INDEPENDENT_QA`

## Predecessor verdict

The independent review in `docs/review/wp38_orientation_correction_independent_qa_record.md`
returned **FAIL — 0 Critical, 1 High, 0 Medium, 0 Low**. H-1 proved that initial WP38 could
coherently rebuild after a source JPEG or materialized validation label had been changed because
its source hashes were self-recorded rather than checked against an independent trust root.

The initial WP38 builder, artifacts, implementation record and QA-FAIL record are preserved.
WP38-R1 is an append-only successor and does not alter the prior evidence.

## H-1 remediation

WP38-R1 now fails before rendering or writing any derived artifact unless all of these checks pass:

1. The exact raw-root path is the canonical repository path
   `data/raw/DATASET01/staging/052bc980a7206f8d/raw`.
2. The pinned WP1 inventory SHA-256 is
   `d45aa7f398a040c44cbc040f4ec005d7e5a8ef50586e905315f76c792ca29022`.
3. Every source image stem `1319..1357` has the exact inventory path, 540x960 dimensions and
   per-file SHA-256 recorded by that authority.
4. Every materialized validation label is independently regenerated byte-for-byte from the pinned
   WP33 boxes and taxonomy using the governed M1 class-index rule. This preserves ten empty labels
   for UNKNOWN-only stems `1319..1328` and exactly 29 class-12/class-14 boxes for `1329..1357`.
5. Repository, raw, image, label and pinned-source path components may not be symlinks; final
   source files must be regular files. Their pinned hashes, rather than link count, define trust so
   concurrent read-only clean-room tests may hold temporary hardlinks without invalidating them.
6. The rejected WP38 base builder is used only as a deterministic pixel/box transform dependency
   and is itself pinned to SHA-256
   `c3b2726241b53be23a9e1b233d38b5dad3994d2f6fc073beabef82f6bd89c23e`.

## Regression evidence

The targeted suite contains real clean-room copies of all governed sources and reproduces both QA
attacks:

- a changed, still-valid 540x960 JPEG at stem `1319` is rejected with a raw-image authority hash
  mismatch;
- a `+0.001` normalized x-coordinate change in stem `1329` is rejected because the materialized
  label differs from the WP33-derived expected bytes.

It also rejects a noncanonical raw root and a canonical-looking raw root containing a symlink
ancestor. Targeted result before re-review: **7/7 PASS**.
